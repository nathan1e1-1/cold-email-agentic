# Delete / Trash

Status: approved · 2026-10-24

## Goal

Delete an outreach thread from the app by moving it to Gmail Trash, with a Trash
view to restore it. Gmail permanently empties Trash after 30 days.

## Decisions

1. **Scope:** add `https://www.googleapis.com/auth/gmail.modify` to the OAuth
   scopes. Existing tokens lack it; a "Reconnect Gmail" action forces the
   consent flow. A 403 from a trash call is surfaced as "Reconnect Gmail to
   enable deleting."
2. **Delete (soft):** a **Trash** button in the reader header calls
   `threads.trash`, deletes the local thread row (cascading messages + card),
   removes it from the Inbox list, and clears the selection. No confirmation —
   Gmail Trash makes it recoverable.
3. **Trash view:** a fourth sidebar item (Inbox, Board, Dashboard, Trash;
   Settings stays bottom-left). Lists trashed outreach threads via
   `in:trash newer_than:30d (from:…)`, cap 20 + Load more. Per row: **Restore**
   (`threads.untrash`). Permanent deletion is not offered in-app: Gmail
   permanently empties Trash after 30 days on its own. (`threads.delete` requires
   the broad `mail.google.com` scope, which we are not requesting.)
4. **Recipients:** the same cold-recipient set as the Inbox (including your own
   address).
5. **Local data:** `Repository.deleteThreadByProviderId(providerThreadId)`
   removes drafts, cards, messages, and the thread (explicit deletes, not relying
   on FK pragmas).
6. **Restore refresh:** after restoring, refetch the Inbox so the thread
   reappears without a manual refresh.

## API

`MailProvider` gains:

```ts
trashThread(id: string): Promise<void>;            // POST /threads/{id}/trash
untrashThread(id: string): Promise<void>;          // POST /threads/{id}/untrash
```

`MailProvider.listThreads` gains `inTrash?: boolean` (query `in:trash …`
instead of `-in:trash`), and `MailboxProvider.listThreads` gains
`ThreadQueryOptions.trashed?: boolean`.

## UI

- `ReaderPane` gets an optional `onTrash` prop; the Inbox passes it.
- `TrashView`: title, empty state, rows (subject, participants, date), Restore, Load
  more, busy states.
- App owns `trashThreads`, `trashToken`, `trashBusy`; loads on entering Trash.

## Tests

- Gmail provider: method/URL for trash and untrash; `inTrash` query shape.
- Adapter: forwards the two methods; trash-mode query passes `inTrash: true`.
- Repository: deleting a thread removes its drafts, messages, and card.
- Manual: trash from the Inbox, see it in Trash, restore it. (No permanent delete in-app.)

## Risks

- Re-consent is required once; a stale token returns 403 until reconnected.
- The Trash list uses the 30-day window; older trashed threads are not shown.
